# Конструктор учебных сценариев — Unity / C#

Тестовое задание: система конфигурируемых учебных сценариев с режимами **Training** и **Exam**, событиями от Unity-компонентов, групповой/последовательной активацией, журналом событий и независимыми анализаторами результатов.

**Репозиторий:** https://github.com/Askar2702/Astana_Tz.git  
**Фактически затраченное время:** 10 часов.  
**Версия проекта:** Unity 6 (`6000.4.1f1`).

## Быстрый запуск

1. Клонируйте репозиторий и откройте корневую папку проекта через Unity Hub.
2. Откройте сцену `Assets/Scenes/Lvll.unity` (она также добавлена в Build Settings).
3. В Hierarchy выберите `ScenarioSystem` → компонент **Scenario Runner**.
4. Убедитесь, что в поле **Scenario** выбран `Assets/Resources/Scenarios/Scenario.asset`; установите **Mode** = `Training` либо `Exam` и соответствующий **Score Analyzer** (`TrainingAnalyzer` или `ExamAnalyzer`). **Logger** = `ConsoleLogger`.
5. Нажмите **Play**. В Game View отображаются режим, активные шаги, прогресс и оценка. Действия выполняются кнопками на сцене; также доступны зоны Trigger/Collision с объектом Player.
6. После завершения используйте **Recalculate** для повторного анализа текущей истории или **Restart** для нового прохождения. Логи смотрите через **Window → General → Console**.

> Изменения в Inspector во время Play Mode действуют для текущего запуска, но обычно не сохраняются после остановки Play Mode. Для постоянной конфигурации меняйте ассеты и настройки вне Play Mode.

## Настройка сценария без программирования

### Шаги и условия

- Откройте `Assets/Resources/Scenarios/`. Шаги хранятся в `Step_01.asset`, `Step_02.asset` и т. д.
- Выберите шаг и настройте **Step Id**, **Description**, **Conditions**. Каждая запись **Event Id** — ожидаемое событие. Для нескольких условий события должны прийти в порядке элементов списка.
- Для нового шага используйте **Assets → Create → Training Scenario → Step**, задайте уникальный идентификатор и условия, затем добавьте ассет в список **Reusable Steps** сценария и в нужные пакеты активации.

### Порядок и режимы

Выберите `Assets/Resources/Scenarios/Scenario.asset`:

- **Reusable Steps** — общий набор переиспользуемых шагов для обоих режимов.
- **Training Batches** — последовательность пакетов тренировки. Все шаги *внутри одного пакета* активируются одновременно и могут выполняться в произвольном порядке. Следующий пакет открывается после завершения текущего. В поставляемой конфигурации тренировка содержит три шага: сначала `Step_01` и `Step_02`, затем `Step_03`.
- **Exam Groups** — экзаменационные группы. У каждой группы есть **Group Name**, **Max Violations** и список **Batches**. Пакеты работают аналогично: параллельные шаги внутри пакета, последовательность между пакетами. В демонстрации три группы, в первой четыре шага.
- **Ignore Inactive Steps** — если включено, события для ещё не активированных шагов игнорируются; если выключено, фиксируются как `OutOfOrder`.

Порядок меняется перестановкой элементов списков в Inspector. Один и тот же `ScenarioStepSO` можно использовать в обоих режимах, не создавая копий.

### Источники событий

Система принимает события через `ScenarioEventBus.Publish(eventId, targetStepId)`:

- **UI Button / UnityEvent**: компонент `ScenarioEventSource` с полями **Event Id** и **Target Step Id**; в `Button.onClick` назначается `ScenarioEventSource.RaiseEvent()`.
- **2D Trigger**: `ScenarioTrigger2D` на объекте зоны, `Collider2D` с `Is Trigger`; проверяется **Required Tag** (по умолчанию `Player`).
- **2D Collision**: `ScenarioCollision2D` на объекте столкновения; проверяется **Required Tag**.
- В кодовой базе также имеются варианты `ScenarioTriggerSource` и `ScenarioCollisionSource` для 3D-физики.

`Target Step Id` рекомендуется задавать, если один `Event Id` может относиться к нескольким шагам. Для своего источника вызовите `ScenarioEventBus.Publish(...)` из нужного Unity callback.

### Анализатор и логгер

В компоненте **Scenario Runner** поля **Mode**, **Score Analyzer** и **Logger** настраиваются независимо. Для нового анализатора создайте наследника `ScoreAnalyzerSO` с реализацией `CalculateScore(IReadOnlyList<ScenarioLogEntry>)` и ScriptableObject-ассет. Для нового логгера — наследника `ScenarioLoggerSO` с методом `Log(ScenarioLogEntry)`.

## Правила прохождения и оценивания

**Training:** нарушение не завершает шаг: пользователь может повторить попытку. Оценка за каждый завершённый шаг — 10 баллов за первую попытку, 5 за вторую, 0 за третью и последующие. В текущей демонстрации максимальная оценка тренировки — **30** (три шага).

**Exam:** нарушение помечает шаг `Failed` без повторной попытки. При достижении порога нарушений в группе остальные незавершённые шаги становятся `Skipped`, затем активируется следующая группа. Итог: `max(0, 100 − 10 × Failed − 5 × Skipped)`.

## Контрольные примеры

**Экзамен без ошибок (100):** нажмите последовательно `button_test`, `button_a`, `button_b`, `button_5`, `button_b_5`, `button_6`, `button_final`, `button_extra`. Итог: 6/6, 100 баллов.

**Экзамен с двумя ошибками (70):** в первой группе нажмите `button_wrong_5` и `button_wrong_2`. Два соответствующих шага получат `Failed`, оставшиеся два — `Skipped`. Затем нажмите `button_final`, `button_extra`. Итог: 70 баллов.

**Повторная оценка:** после успешного экзамена, *не выходя из Play Mode*, замените в `Scenario Runner` поле **Score Analyzer** с `ExamAnalyzer` на `TrainingAnalyzer`. Нажмите **Recalculate**: для шести шагов, выполненных с первой попытки, результат станет 60. История прохождения не сбрасывается.

**Тренировка:** для проверки оценки 10 + 5 + 0 = 15 необходимо завершить один шаг с первой попытки, другой — со второй, третий — с третьей; ошибки направляйте в активный шаг через его `Target Step Id`.

## Журнал и повторный анализ

`ScenarioHistory` хранит структурированные `ScenarioLogEntry`: UTC-время, `EventId`, `StepId`, `Result`, число попыток и нарушений. `ConsoleScenarioLoggerSO` выводит записи в Console. После окончания `ScenarioRunner` выводит историю и итоговую оценку. **Recalculate** применяет выбранный анализатор к уже собранной истории без нового прохождения.

История хранится **в памяти текущего прохождения**; при `Restart` и новом запуске очищается. Постоянное сохранение на диск не реализовано.

## Архитектура

| Компонент | Ответственность |
| --- | --- |
| `ScenarioConfigSO`, `ScenarioStepSO`, `StepBatch`, `ExamGroup` | Настройки шагов, условий, порядка активации и групп в Inspector |
| `ScenarioRunner` | Запуск/перезапуск, активация пакетов и групп, маршрутизация событий, завершение сценария |
| `StepRuntime` | Состояние конкретного шага, порядок условий, попытки и нарушения |
| `ScenarioEventBus`, `ScenarioEvent` | Общий интерфейс передачи событий от UI/физики/пользовательского кода |
| `ScenarioHistory`, `ScenarioLogEntry` | Структурированная история событий и результатов |
| `ScenarioLoggerSO`, `ConsoleScenarioLoggerSO` | Расширяемое логирование |
| `ScoreAnalyzerSO`, `ScenarioAnalyzer`, реализации анализаторов | Независимый расчёт результатов по журналу |
| `ScenarioStatusUI` | Отображение режима, активных шагов, прогресса и оценки |

**Как расширять:** новый источник событий публикует событие в `ScenarioEventBus`; новый тип оценивания наследует `ScoreAnalyzerSO`; новый способ вывода журнала наследует `ScenarioLoggerSO`. Для изменения модели условий или алгоритма активации потребуется расширить соответствующие `StepRuntime` / `ScenarioRunner`: отдельного подключаемого интерфейса для исполнителей в текущей реализации нет.

## Ограничения

Проект демонстрирует логику сценариев, а не художественную часть. Постоянное хранение результатов, отдельный визуальный конструктор, редакторская валидация и полностью подключаемые стратегии исполнения не входят в текущую реализацию. Изменение **Mode** во время уже запущенного сценария не предназначено для переключения его структуры: выберите режим до запуска или перезапустите сценарий с нужной конфигурацией.
